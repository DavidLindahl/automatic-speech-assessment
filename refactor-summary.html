01 / Context

Why the cleanup was needed.

The codebase had accumulated dead weight from three pivots: the AB-paradigm cut on 2026-04-13, the QualiSpeech and Sound-Wheel direction abandoned earlier, and the descriptor-discovery framing that is now historical.

Active scope is Qwen2-Audio + ALLD descriptive speech-quality assessment with temporal localization on NISQA-SIM mixes. The HPC pulls from main on every job, so every change had to keep the live training path deployable while the cleanup ran.

03 / Method

Decisions that kept main always-deployable.

  • Per-phase branches, fast-forward merge to main between phases. main stayed shippable at every step, which mattered because the HPC pulls it on every submission.
  • Hard rule before any merge: ssh dtu bjobs empty, or an explicit green-light. Surprises on a live queue are how relationships with IT depart.
  • Three verification gates per phase: the test_jobs.py canary, jobs/_lib/lint-budget.sh as the LSF firebreak, and bash -n against every touched script.
  • Coordination with David, the repo co-owner, for any phase that touched shared modules: data.py, processed_data.py, inference.py. No surprise renames on jointly-edited surfaces.
04 / Notes

Two callouts worth keeping.

The firebreak

LSF rusage[mem] is per-core, not per-job.

With -n 8, rusage[mem=64GB] requests 512 GB total, not 64. Getting this wrong has previously triggered angry emails from DTU IT and killed the entire pending queue.

jobs/_lib/lint-budget.sh now enforces queue caps statically. Submission-time arithmetic, not post-mortem arithmetic.

The gotcha

Never run git inside ~/Library/Mobile Documents/.

Mid-session, iCloud auto-switched the checkout to an old branch from March. Stash auto-saved the work in flight, nothing was lost.

It still serves as a reminder that running git inside an iCloud-synced tree is fundamentally risky. The repo proper lives under ~/code/, where it should.
