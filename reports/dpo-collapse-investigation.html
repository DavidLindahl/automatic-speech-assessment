Why paper-faithful DPO/ALLD collapsed — and the fix

Investigation 2026-05-20 · branch fix/dpo-label-mask · repo DavidLindahl/automatic-speech-assessment
Root cause found and fixed. The paper-faithful DPO run collapsed because ALLDDPOCollator._build_labels computed the prompt mask wrongly under the Qwen2-Audio processor's default left-padding. The model was trained to predict the prompt (<|AUDIO|> tokens, "Please describe...") instead of the response — corrupting next-token distributions and driving the policy to mode-collapse. The fix (force right-padding + derive prompt length from the attention mask) is verified on the real failed-run data by DTU diagnostic 28481296: "Label masks look correct on all rows."
What is not yet proven. The end-to-end claim — "the fix makes a full DPO run train without collapsing" — is strong inference, not yet a direct demonstration. A 256-sample smoke training job is written and merged (jobs/train/dpo_labelmask_smoke_h100.sh) but could not be submitted: every DTU GPU queue currently rejects multi-core jobs with a 4 > ! esub error. The smoke run is the last confirmatory step.

1. The failure

The paper-faithful DPO run 28383641 (LR 1e-6, β 0.4, 1 epoch, on the cleaned 9979-row dataset) trained to completion and looked healthy: train_loss=0.21, rewards/accuracies=1.0, reward margins 7–14. It pushed a checkpoint to the Hub. But both evaluations (28386489 greedy, 28386490 sampled) showed the model had collapsed:

2. The smoking gun in the training log

The reward telemetry from dpo_paper_half_h100_28383641.out already diagnoses the failure type. Sampled lines: 

rewards/chosen:   -0.72  -3.94  -3.36  -1.09  ...  -6.50  -7.69
rewards/rejected: -10.5  -9.4   -7.4   ...           -15.2
rewards/accuracies: 1.0   (throughout)

In healthy DPO, rewards/chosen stays near zero or trends slightly positive: the policy raises the log-prob of the preferred completion above the reference. Here rewards/chosen is consistently and increasingly negative — both chosen and rejected log-probs are pushed far below the reference; rejected just falls faster. accuracies=1.0 hides this because "chosen > rejected" is still satisfied while both collapse.

This is the textbook fingerprint of the policy running away from the entire response distribution — learning to suppress all captions, then defaulting to one boilerplate string. It matches the eval collapse exactly. The clean train_loss and accuracies=1.0 are not evidence of success; they are consistent with a model that has learned a degenerate shortcut.

3. The ALLD method is fine — the bug is in data plumbing

We checked the ALLD loss against the paper (Chen et al., arXiv 2501.17202v2, §4.2). The paper's Eq. 2: 

L_ALLD = -log σ( β·log[πθ(y_t|x) / π_ref(y_t|x)]
                  - β·log[πθ(y_a|x) / π_ref(y_a|x)] )

  y_t = preferred  (expert / chosen caption)
  y_a = dispreferred (audio-LLM sampled / rejected caption)
  πθ   = Qwen2-Audio policy   (scores BOTH completions, audio-conditioned)
  π_ref = expert text LLM       (scores BOTH completions, meta-info conditioned)

Our ALLDDPOTrainer.compute_loss implements exactly this: logits_diff = (policy_chosen - ref_chosen) - (policy_rejected - ref_rejected), loss = -logsigmoid(β · logits_diff). The crucial ALLD-specific choice — π_ref is an expert text model conditioned on the meta-info, not a frozen copy of the policy — is correctly implemented (ref_model_id = "Qwen/Qwen2-7B", separate text stream). The loss math is paper-faithful. The collapse is not in the ALLD formulation; it is in how training labels are built.

4. Root cause: label-mask misalignment under left-padding

ALLDDPOCollator._build_labels masked the prompt by computing a per-row prompt_len from a separately padded prompt-only batch, then doing labels[:prompt_len] = -100 on the full batch. That is only correct if the real prompt starts at index 0. It does not:

Verified locally 2026-05-20:

  • The Qwen2-Audio processor tokenizer defaults to padding_side = 'left'.
  • Under left-padding the real prompt starts after a variable run of PAD tokens, so labels[:prompt_len] masks leading PADs and leaves the actual prompt supervised as the response.
  • The reference model Qwen/Qwen2-7B has pad_token_id == eos_token_id == 151643, so any prompt-length logic keyed on token id (not the attention mask) is also unreliable.

Why the May 7 revert was wrong

The right-padding fix landed once (commit 78e2161) and was reverted the next morning (150c5a4) with the argument: "the dpo_plus2epoch eval worked with left-padding, so left-padding is fine." That does not follow. "A different run was less corrupted" is not "this code path is correct." The plus2epoch run may have had lower prompt-length variance or a different SFT base; it does not prove the mask is right. The local simulation and diagnostic 28481296 show the mask is unambiguously wrong under left-padding regardless of which run consumed it. After the revert, the LR was dropped 5e-6 → 1e-6 as a workaround — but run 28383641 at LR 1e-6 still collapsed, because the real bug was untouched.

5. The fix

Commit 31cda26 on fix/dpo-label-mask:

  • Force padding_side = 'right' on both the policy and reference tokenizers in ALLDDPOCollator.__init__, so the prompt is an exact prefix and labels[:prompt_len] masks only the prompt.
  • Rewrite _build_labels to take per-row prompt lengths derived from the prompt-only attention_mask (a sum of 1s), not from token_id != pad_id. This is robust even when pad_token_id == eos_token_id (the Qwen2-7B reference case).
  • Add a strict test in tests/test_alld_pipeline.py that decodes the supervised labels and asserts they equal the response with no prompt tokens leaking — the old test only checked tensor shapes and would pass even with the bug live.

Verified: after the fix, zero <|AUDIO|> tokens appear in any supervised label span, on both the local simulation and DTU diagnostic 28481296.

Minor residual (not the collapse cause): the supervised span occasionally drops the first response token (e.g. ' synthesized' instead of 'This synthesized') because prompt-only vs full tokenization can differ by one token at the boundary. It is consistent, ~1 token of ~30, and cosmetic. Worth a small follow-up but does not affect the collapse fix.
